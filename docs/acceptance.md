### Installed Claude Code input-isolation acceptance

On 2026-09-30, the same installed plugin and native module were tested with 21 actual Claude Code CLI processes, 21 tool uses and 21 returned results. Two temporary AppKit apps supplied four controlled windows and recorded their own input events, source PIDs, text, foreground app, pointer positions and modifier flags. The user was away from the computer, so one CC session simulated foreground user activity while another drove background CU operations. This is automated input-path acceptance, not a human hardware keyboard/mouse test.

There were 44 successful background text-effect checks: 12 while the simulated user held Shift, 12 while it held/released Command, 10 while it switched between two foreground windows, and 10 while it moved the pointer and typed. Background AX button actions and window capture also succeeded. Event source PIDs remained separate, background text events had no inherited modifier flags, sibling target windows were unchanged, and the foreground app remained the user fixture. Static-pointer phases preserved the pointer and clipboard change count. The moving-pointer phase recorded 27 simulated user moves and 28 pointer-state changes, all matching the user trajectory or its final restoration; the CU added no unexpected pointer position.

Reset and a three-second CU timeout were injected while the other session continued Shift-modified foreground typing. Each user session completed 45 further inputs with Shift retained. Reset reported zero released CU keys/buttons and stopped only its own native/worker processes. Neither case produced the scheduled late text; subsequent background and foreground input recovered successfully. Fourteen background guard checks were correctly refused without input or focus changes: 13 native failures remained visible in diagnostics despite being caught, and one JS input-scope check failed before native dispatch. These refusals do not establish background coordinate mouse or raw-key capability.

Five tool results set `is_error`: two deliberate reset/timeout cases and three functional assertion failures for background Command-A. In the inactive NSTextView fixture, the chord reported `dispatched` but did not select existing text, so subsequent typing appended. A no-concurrency control reproduced this behavior while the same foreground chord worked; a compact failure reproduced all three mismatches with complete diagnostics. Two earlier long failure returns were shortened in the CC stream around 10,000 characters, so their full JSON assertions could not be parsed. AX value replacement followed by background typing passed, but it does not make the keyboard shortcut successful.

Full operation-isolation acceptance remains unmet: background coordinate clicks, scrolling, dragging and raw key holds require shared foreground input, inactive-app shortcuts require effect verification, and concurrent physical hardware input remains untested. The run did not change production code or global host configuration. Temporary apps, registrations, screenshots, harnesses and records were removed after validation; 49 recorded CC/native/worker PIDs were confirmed stopped and no owned control socket remained.
