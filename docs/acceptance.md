### Stable capture URL and local reminder acceptance (0.4.5)

On macOS 27.0 (26A428), replayd's actual `ScreenCaptureApprovals.plist` contained separate reminder records for nine hash-named Agent Enhance app URLs, each starting a new reminder period despite identical signing. Native 0.4.5 now installs the real signed app at the stable `<runtimeRoot>/native-computer/Agent Enhance Computer.app` URL, tracking payload bytes separately. An OS file lock covers installation through startup; same-payload instances can coexist, and a different payload is refused with `RUNTIME_UPGRADE_REQUIRED` while an owned native instance is alive. Normal cleanup removes its live registration; installer process death releases the OS lock without manual intervention. Fixed signing, initial OS permission requirements and default isolated-only policy are retained.

Two failed prototypes are counted explicitly. A PID-file lock's abandoned-owner test failed, so it was replaced with the OS file lock. In the first live upgrade probe, five captures succeeded but the still-running original service's next capture failed with a ScreenCaptureKit TCC refusal after its bundle was replaced. That process had reported preflight permission true. The final guard refuses replacement before file changes and the original process continues capturing successfully. An initial local reminder-date write was also overwritten by replayd's cached record; the final adjustment used `defaults` and reloaded only the user's preference/capture-reminder services before testing.
